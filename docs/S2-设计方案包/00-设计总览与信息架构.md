## 1. 产品定位与设计概念

### 1.1 定位

「荣河读书」是博物馆面向读者的阅读伴读小程序：以博物馆书单为源头，陪伴读者**选书 → 阅读 → 记录 → 坚持**。它是文化机构的延伸，不是互联网商城，也不是阅读社交平台。

### 1.2 设计概念：「数字书斋 · 钤印为证」

- **书斋**：整体气质取自中式书斋——宣纸底色、墨色文字、黛蓝骨架、细线框、衬线标题。安静、克制、有纸感。
- **钤印**：将"打卡"具象为**盖印章**——读完一日即钤一印。打卡日历上，已读日是嵌在月历格里的一枚朱砂小印；目标完成时首页盖下一枚"今日已阅"印。成就感来自仪式感，而非连击数字。
- 概念一以贯之的落点：

| 概念 | 落点 |
|---|---|
| 宣纸/墨/朱砂 | 全局色板（见 01 视觉方向） |
| 衬线标题 | 页面主标题、书名、大数字 |
| 印章 | 打卡日历的日格、目标达成徽记、按钮高亮态 |
| 册页/笺 | 卡片 = 纸笺：小圆角、细边框、微纸纹底 |

### 1.3 设计原则（评审与实现的共同准绳）

1. **一屏一事**：每个页面有一个主任务（首页=今天读没读，计时=专注，统计=回望），辅助信息让位。
2. **数据有源**：界面每个数字必须指向真实 API；无数据支撑的模块一律不做（S1 的假"活动/笔记"模块是反面教材）。
3. **状态完备**：每页必答四问——加载中显示什么？空数据显示什么？请求失败显示什么？未登录显示什么？
4. **真实可达**：所有可点元素必须有落点页面；导航闭环可从任意页回到四个 Tab。
5. **克制的动效**：只保留三类——打卡盖印（0.4s 缩放+落定）、页面转场（系统默认）、进度条生长（0.3s）。无其余动效。

## 2. 信息架构与导航

### 2.1 底部导航（TabBar 4 项，修复 S1 导航断裂）

| Tab | 名称 | 图标语义 | 承载 |
|---|---|---|---|
| 1 | **首页** | 书斋/灯 | 今日目标钤印卡、继续阅读、本周书单 |
| 2 | **书库** | 书列/册架 | 全部书目、分类筛选、搜索、书籍详情入口（**新增页，解 S1 选书死锁**） |
| 3 | **书架** | 书堆 | 我的书：想读/在读/已读，进度管理 |
| 4 | **我的** | 人/印 | 账户、统计入口、设置、关于 |

实现注记（S3）：采用底座既有组件式 tabBar（`components/tabbar/tabbar.vue` 恢复启用并改造四项），配色与选中态按 01 视觉方向覆盖；不新增原生 tabBar 机制。

### 2.2 页面结构图

```
TabBar
├─ 首页 pages/index/index
│   ├─→ 阅读计时（带 bookId）        [功能页]
│   ├─→ 书籍详情?id=                 [功能页]
│   └─→ 书库（查看更多书单）
├─ 书库 pages/library/index ★新增
│   ├─ 分类 chips（横向滚动）/ 搜索
│   ├─ 书籍详情?id=                 [功能页]
│   │   ├─ 加入书架（想读）
│   │   ├─ 已在架 → 继续阅读 / 更新进度（页码步进器）
│   │   └─→ 阅读计时（带 bookId）
│   └─ 空态：书单筹备中
├─ 书架 pages/bookshelf/index
│   ├─ Tab：想读(n)/在读(n)/已读(n)   [角标计数]
│   ├─ 在读卡 → 继续阅读 / 更新进度
│   ├─ 想读卡 → 开始阅读（首阅即转在读）
│   ├─ 已读卡 → 完成日/重读
│   └─ 空态 → 「去书库逛逛」按钮（闭环）
└─ 我的 pages/user/center
    ├─ 未登录态：登录引导卡 → 底座登录页
    ├─ 已登录态：头像/昵称/读者号
    ├─ 三格统计摘要（点击 → 统计页）
    ├─ 菜单：我的书架/阅读统计/关于我们/联系客服/设置（协议）——仅真实可达项
    └─ 退出登录

功能页（非 Tab）
├─ 阅读计时 pages/reading/timer ★全屏沉浸（夜读视觉）
│   状态机：ready → running ⇄ paused → 确认结束 → 成果弹层
├─ 阅读统计 pages/stats/index ★自定义导航含返回键（修 S1）
│   ├─ 三卡：今日/本周/累计
│   ├─ 本周柱状图（自适应单位）
│   ├─ 打卡月历（钤印日格）
│   └─ 明细行
└─ 登录/注册/协议/客服：复用底座页（视觉换肤程度见 01 §5）
```
