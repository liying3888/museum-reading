## 一、规格两条补文复核（E 条，02 行 35 / 行 168）

**行 35「240 分钟自动结束的执行主体」——核心诉求已答，一个口径缝未合。**

- 我 R2-P1-2 问的「谁执行、用户不在场怎么办」：后端权威+服务端墙钟扫描+不依赖前端在线+前端在场双通道+重复结束幂等返回——杀进程/断网场景闭环成立，「纸面兜底」的指控解除 ✓。
- **残留洞（新，P2）：paused 会话不在扫描口径内。**原文「服务端墙钟扫描**运行中**会话」——字面只含 running。我 23:30 接电话暂停忘了：按净时长到不了 240 线，会话无限悬挂；按 start 墙钟起算则暂停中也会被自动结束。两种口径行为完全相反，规格未写适用哪种。行 168 只承诺「paused 重入恢复 paused」——若我次日不回来，这个会话永久悬空（净时长冻结、归属日不定）。建议补一句：「扫描范围=未结束会话（running/paused），达 240 分钟按 start 墙钟判定、按净时长落记录」或「paused 超 X 分钟自动结束」二选一明示。

**行 168「悬置会话重入」——同书三场景全定义，异书路径漏了（新，P1）。**

- 同书重入：杀进程再进 ✓（恢复 running 按 §0.3 重算）、切后台再进 ✓（onShow 重算）、换入口进 ✓（首页/书架「继续阅读」均恢复现态+按钮变「回到计时」）——R2-P1-1 的主体场景闭环 ✓。
- **洞（P1）：进行中会话属于他书时的行为未定义。**补文括号限定「（首页继续阅读/书架继续阅读入口）」+「（同书直进）」——design 只考虑了同书。我昨晚暂停了三体没结束，今晚从书架点**百年孤独**的「继续阅读」（或经快选抽屉选中它）：按 S3 落地条款「start 接口幂等（带未结束会话则返回该会话**而非新建**）」——返回的是三体的旧会话。轻则计时页显示的书与我的意图错位，重则百年孤独的阅读时长全记到三体头上；按规格字面实现，「换书」这个多本在读的日常路径在旧会话悬置期间没有入口。这打回「记录可信」，且会被 S3 幂等条款固化为接口行为。补一句即可：「进行中会话属于他书时：paused 态先自动收口落记录再新建新会话（或弹提示要求先结束），不得跨书恢复」。
- 次要残留（P3，不立案只记）：用户不在场被 240 自动结束后，主动告知形态未定义（「下次拉取记录时即可见」是被动可见，开 app 弹什么/怎么引导去删无条款）；悬置会话跨午夜归属日仍无条款（R2-P2-3 旧账，与上面 paused 口径洞同根）。
