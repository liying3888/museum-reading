## 新发现问题

### P1

1. **悬置会话重入未定义（真暂停修复引出的新闭环洞）。** §5.1 允许 running/paused 离开页面保持态（「计时仍在进行」），但状态机只有 `ready --开始--> running` 一个入口：我退出计时页回首页，再点「继续阅读」（或书架/详情的入口）进计时页——是恢复 running/paused，还是回到 ready 再调一次 start？§5.4 只写了 onShow 重算显示时间，没写会话恢复。若按 ready 处理就产生双会话/旧会话悬置，今日累计可能双计——这恰恰又打回「记录可信」。连带：paused 态悬置（比如暂停后忘了）按净时长永远到不了 120/240 触发线，会话无限悬挂，次日电开 app 面对的是什么态，规格无一处提及。需要三句话补齐：进计时页先查进行中会话→有则恢复态；各入口按钮遇进行中会话的行为；跨天悬置会话的收口。
2. **240 分钟自动结束的执行主体与「不在场告知」未定义，兜底②在最高发场景可能空转。** 「忘记结束」的典型场景是小程序被划掉/微信被杀——此时前端既弹不出 120 分钟提醒也不会执行 240 分钟结束。§0.3② 未写由服务端兜底（定时或懒结算）；「成果弹层注明『长时间未操作已自动结束』」也预设用户在场——用户第二天回来时的告知路径（开 app 弹什么、记录标在哪、怎么引导去删）无节无画板。若实现落在前端，这层兜底等于纸面兜底。

### P2

1. **修正只删不改。** §0.3③ 只能删除整条异常记录。一夜空转 8 小时里若真读了 1 小时，我只能整条删（1 小时白读）或整条留（8 小时污染）二选一。建议「阅读记录管理」支持改时长（或至少删前显示该条时长供判断），否则修正入口对付「部分污染」是钝刀。
2. **「在读快选」抽屉无画板、卡身无可点暗示**（承接核验 P1-5）：round1-P1 级修复的主视觉缺席，且连一个「点卡切换 ▾」级提示都没有。快选是本修的可用性核心，画板不补，C 端 L1 原型定稿闸门意义上这条修复没法定稿。
3. **跨午夜会话归属日未定义。** §6.2 打卡判定用东八区日期、§6.1 的今日/本周/月历钤印全按日切，但 23:10-00:40 的会话记哪天、钤哪天的印，规格无条款。对「连续打卡 n 天」这种我天天盯的数字，跨午夜一笔算错就是断签冤案。
4. **修正路径藏两层+无视觉。** 入口=我的→设置（底座页）→阅读记录管理（§7.1.4），从发现统计被污染到完成修正要 5 步且管理页零画板。被污染的用户本来就有情绪，这条路径值得直提一级（如统计页右上「…」内）。

### P3

1. paused 态离开页面的 Toast 文案仍是「计时仍在进行」（§5.1），与暂停态不符，应为「计时已暂停」类。
2. board10 paused 帧最底部常驻提示行疑似仍抄 running 态的「计时中 可切后台不打断」（§5.2 只定义了 running 态常驻行）——判读待核；若属实，文案应随态切换。
3. 手势可发现性：长按置顶（§4.1.2）与右滑移出（§4.2，round1 P2-4 旧账）都无任何提示元素，首次全靠猜；置顶态卡片示样也缺（待核）。
4. 三格统计条累计格仍为小时（双显），与今日/本周分钟跨格不同基（§6.1.2）——双显已大幅缓解，存档为轻微项。
5. 120 分钟 remind 弹层（§0.3①/§5.1）期间能否先按暂停未定义——我读书被打断的第一反应是暂停而不是二选一。
6. board10 成果卡数值自洽性待核：结构完全符合 §5.3（印+本次时长+三行小结+「好的」），但今日累计/连续/距目标差的小字号数字判读不稳，请按「今日累计 ≥ 本次、距目标差 = max(0, 目标−累计)、与达成印互斥」复核示样。
